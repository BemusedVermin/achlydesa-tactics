# P1-10 — ach_logistics: stocks and consumption

**Agent:** task-implementer · **Size:** M · **Depends on:** P1-02 · **Branch slug:** logistics-stocks · **Runs on:** either

## Goal
Water runs out in the desert. Represent the caravan's stocks and their consumption with exact integer accounting, so a three-day march can be forecast precisely, and so thresholds ("water below a quarter") can be scheduled as events rather than polled.

## Specification
```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub enum StockKind { Water, Food, Fuel, Ammunition, Parts, Medicine }  // Water is separate per High-Level Design §11.3
// Base units: Water = liter, Food = ration (one person-day), Fuel = liter, Ammunition = round,
// Parts = kit, Medicine = treatment. Milli(1000) = one base unit.

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub enum Activity { Marching, Halted, Resting }

#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct StockSet { amounts: BTreeMap<StockKind, Milli> }
impl StockSet {
    pub fn get(&self, k: StockKind) -> Milli;
    pub fn add(&mut self, k: StockKind, q: Milli) -> Result<(), LogisticsError>;          // overflow ⇒ Err
    pub fn remove(&mut self, k: StockKind, q: Milli) -> Result<(), Shortfall>;          // never goes negative
    pub fn remove_up_to(&mut self, k: StockKind, q: Milli) -> Milli;                    // returns amount actually removed
    pub fn transfer(from: &mut StockSet, to: &mut StockSet, k: StockKind, q: Milli) -> Result<(), Shortfall>;
    pub fn iter(&self) -> impl Iterator<Item = (StockKind, Milli)>;
}
pub struct Shortfall { pub kind: StockKind, pub requested: Milli, pub available: Milli }

/// Per-person, per-hour rates by (kind, activity), in Milli.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct ConsumptionTable { pub rates: BTreeMap<(StockKind, Activity), Milli> }
impl ConsumptionTable { pub fn load(path: &Path) -> Result<Self, LogisticsError>; }

/// Exact cumulative consumption: floor(rate_per_hour * persons * elapsed_ms / 3_600_000), in i128.
pub fn cumulative(table: &ConsumptionTable, kind: StockKind, activity: Activity, persons: u32, elapsed: SimDuration) -> Milli;

/// Consumption over [t0, t1] within ONE activity segment that began at seg_start, computed as
/// cumulative(t1 - seg_start) - cumulative(t0 - seg_start), so splitting an interval never changes the total.
pub fn consumed_between(table: &ConsumptionTable, kind: StockKind, activity: Activity, persons: u32,
                        seg_start: SimTime, t0: SimTime, t1: SimTime) -> Milli;

/// Smallest elapsed duration (ms) since segment start at which cumulative consumption reaches `target`; None if the rate is 0.
pub fn time_to_consume(table: &ConsumptionTable, kind: StockKind, activity: Activity, persons: u32, target: Milli) -> Option<SimDuration>;
```

### `content/logistics/consumption.ron` (tuning values, not canon)
Marked `status: "TUNING"`. Water: Marching 450, Halted 200, Resting 150 mL per person-hour. Food: 42 milli-rations per person-hour in every activity. All other kinds are 0 for Phase 1. Cite High-Level Design §11.3 on water in desert operations.

## Acceptance
- **Splitting invariance (property):** for random persons, activity, segment start, and a sorted list of cut points, the sum of `consumed_between` over the pieces equals `consumed_between` over the whole.
- `time_to_consume` is exact: `cumulative(t) >= target` and `cumulative(t − 1 ms) < target` (property).
- **Conservation (property):** random sequences of add/remove/transfer between two sets conserve the total per kind, and never produce a negative amount.
- `cargo xtask ci` passes.
