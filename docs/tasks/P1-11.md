# P1-11 — ach_sim: march simulation

**Agent:** task-implementer · **Size:** L · **Depends on:** P1-04, P1-07, P1-08, P1-09, P1-10 · **Branch slug:** sim-march · **Runs on:** either

## Goal
The first living thing in Achlydesa: a caravan column marching across real terrain on the event-driven clock, through desert march windows and short halts, drinking its water, and journaling everything that happens. There is no combat or AI yet, but days pass in one run, and every step is exact and replayable. This is the skeleton the command model will later animate.

## Specification

### Scenario (`scenario.rs`)
```rust
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct Scenario {
    pub id: String, pub seed: u64,
    pub start: String, pub end: String,                  // "D1 05:00" format (SimTime FromStr)
    pub terrain_dir: String, pub roster: String, pub profiles: String,
    pub consumption: String, pub routes: String, pub sites: String,   // paths relative to the repo root
    pub columns: Vec<ColumnSpec>,
}
pub struct ColumnSpec {
    pub name: String, pub leader: String, pub reporters: Vec<String>,   // character keys
    pub persons: u32, pub profile: String, pub posture_permille: i32,   // guarded foot column ≈ 620
    pub stocks: BTreeMap<StockKind, i64>,                                // Milli
    pub start_site: String, pub legs: Vec<LegSpec>, pub schedule: ScheduleSpec,
}
pub enum LegSpec { FollowRoute { route: String, to_site: String }, CrossCountry { to_site: String } }
pub struct ScheduleSpec { pub windows: Vec<(String, String)>, pub march_minutes: u32, pub halt_minutes: u32 } // ("05:00","11:00")
impl Scenario { pub fn load(path: &Path) -> Result<Self, SimError>; }
```
Sites file format is P0-06's `red_ledger_sites.ron`; parse `(id, name, kind, pos: (x_m, y_m), …)` into `BTreeMap<String, Site>` in `content.rs`, ignoring unknown fields.

### Legs and kinematics (`kinematics.rs`)
- `FollowRoute`: the route's nearest vertices to the column's current site and to `to_site` bound the leg; points come from `route_path`. Then prepend the exact site position and append the exact destination, if they differ.
- `CrossCountry`: `NavQuery::find_path` with `max_expansions = 4_000_000`.
- Precompute per leg, for each segment i:
  - `len_mm`;
  - `slope‰` from `height_cm` at segment endpoints;
  - `speed_mm_s = base_speed(slope) × surface_factor × posture_permille / 10⁶`, where surface_factor is the route condition's road factor for `FollowRoute` and `offroad_factor` for `CrossCountry`;
  - `march_ms = len_mm × 1000 / speed`, with a minimum of 1;
  - cumulative arrays `cum_len_mm[]` and `cum_march_ms[]`.
- `position_at_march_ms(t)`: find the segment by binary search and interpolate with `WorldPos::lerp_permille`.
- A segment with impassable slope ⇒ `SimError::ImpassableLeg { column, leg, segment }` at scenario load. This is fail-fast; Phase 3 turns it into a decision request.

### Schedule (`schedule.rs`)
```rust
pub struct MarchSchedule { windows: Vec<(SimDuration, SimDuration)>, march: SimDuration, halt: SimDuration }
impl MarchSchedule {
    /// Activity at wall time t for a column that is under way.
    pub fn activity_at(&self, t: SimTime) -> Activity;
    /// Marching milliseconds accrued in [a, b).
    pub fn marching_between(&self, a: SimTime, b: SimTime) -> SimDuration;
    /// Earliest wall time t ≥ from at which marching_between(from, t) == need.
    pub fn wall_time_after_marching(&self, from: SimTime, need: SimDuration) -> SimTime;
    /// Next boundary (window start/end, halt start/end) strictly after t, with its kind.
    pub fn next_boundary(&self, t: SimTime) -> (SimTime, Boundary);
}
```
- Within each window, cycles of `march` then `halt` begin at the window start. A final partial cycle is truncated at the window end.
- Outside windows the activity is `Resting`.
- Windows must not overlap or cross midnight (validated at load).

### Events (`events.rs`)
```rust
pub const SCHEMA_VERSION: u32 = 1;
pub mod phase { pub const DAY: u8 = 0; pub const SCHEDULE: u8 = 10; pub const ARRIVAL: u8 = 20; pub const STOCK: u8 = 30; pub const END: u8 = 250; }

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum SimEvent {
    ScenarioStarted { scenario: String },
    DayBegan { day: i64 },
    ColumnDeparted { column: ColumnId, site: String, pos: WorldPos },
    MarchWindowStarted { column: ColumnId, pos: WorldPos },
    MarchWindowEnded { column: ColumnId, pos: WorldPos, marched_today_m: i64 },
    ShortHaltBegan { column: ColumnId, pos: WorldPos },
    ShortHaltEnded { column: ColumnId, pos: WorldPos },
    SiteReached { column: ColumnId, site: String, pos: WorldPos, distance_from_start_m: i64 },
    StockThreshold { column: ColumnId, kind: StockKind, remaining: Milli, remaining_permille: PerMille },
    StockExhausted { column: ColumnId, kind: StockKind },
    ColumnDayEnded { column: ColumnId, day: i64, distance_today_m: i64, stocks: StockSet, pos: WorldPos },
    ColumnArrived { column: ColumnId, site: String, pos: WorldPos, total_distance_m: i64, elapsed: SimDuration },
    ScenarioEnded { reason: EndReason },
}
pub enum EndReason { AllArrived, TimeLimit }
```
`ach_core::define_id!(ColumnId)` lives in `column.rs`.

### Column state (`column.rs`)
Serializable. It holds:
- identity, leader and reporters (`CharacterId`), persons, stocks;
- the precomputed legs, the current leg index, and the `march_ms` done in the current leg;
- `last_update: SimTime`, the current activity and its segment start;
- the next-threshold bookkeeping per kind (thresholds 500‰, 250‰, 100‰ of the **initial** amount, each fired once), and `arrived: bool`.

### Simulation loop (`sim.rs`)
```rust
pub struct Sim { /* state: SimState (serializable); terrain, content: Arc<…> (reloaded from scenario on load) */ }
#[derive(Serialize, Deserialize)] pub struct SimState {
    pub scenario_id: String, pub seed: Seed, pub ids: IdAllocator, pub roster: Roster,
    pub columns: BTreeMap<ColumnId, Column>, pub scheduler: Scheduler<SimEvent>,
    pub journal_next_seq: u64, pub journal_fingerprint: u64, pub end: SimTime,
}
impl Sim {
    pub fn new(scenario: &Scenario, repo_root: &Path) -> Result<Self, SimError>;
    pub fn now(&self) -> SimTime;
    pub fn state(&self) -> &SimState;
    /// Processes the next event: brings every affected column's accounting up to the event time, applies the event,
    /// journals it, and schedules consequences. Returns None when the queue is empty.
    pub fn step<W: Write>(&mut self, journal: &mut JournalWriter<W>) -> Result<Option<SimTime>, SimError>;
    pub fn run_until<W: Write>(&mut self, limit: SimTime, journal: &mut JournalWriter<W>) -> Result<RunSummary, SimError>;
    pub fn column_position_at(&self, column: ColumnId, t: SimTime) -> Option<WorldPos>; // valid for t ≥ last_update
    pub fn journal_header(&self) -> FileHeader;   // magic ACHJ, SCHEMA_VERSION, seed, label = scenario id
}
pub struct RunSummary { pub end_time: SimTime, pub events: u64, pub arrived: Vec<(ColumnId, SimTime)>, pub fingerprint: u64 }
```

Rules:
1. **Initialization** schedules:
   - `ScenarioStarted` at start (phase DAY);
   - `DayBegan` at each midnight up to `end`, lazily (each DayBegan schedules the next);
   - per column, `ColumnDeparted` at start, then the schedule boundary events;
   - `ScenarioEnded(TimeLimit)` at `end` (phase END).
2. **Accounting update** before handling any column event at time t:
   - split [last_update, t) at activity boundaries;
   - add marching ms to leg progress;
   - apply `consumed_between` for each kind using `remove_up_to`;
   - set last_update = t.
   The result must be independent of how many events occurred in between (see Acceptance).
3. **Only one pending column event per column:** the earliest of the next schedule boundary, the next site or leg end, and the next threshold crossing. After handling it, compute and schedule the next one.
   - Site and leg ends are found with `wall_time_after_marching`.
   - Threshold crossings are found by walking forward over activity segments with `time_to_consume`, bounded by `end`.
4. `ColumnDayEnded` is scheduled at 23:59:59.999 for each column not yet arrived, and once on the arrival day.
5. On final arrival: `ColumnArrived`. The column switches to `Resting` permanently (it still consumes). No further schedule boundaries.
6. When all columns have arrived, schedule `ScenarioEnded(AllArrived)` at the arrival time (phase END). Scenario end stops the loop.
7. `StockExhausted` fires once when a kind reaches 0. Phase 1 applies no other consequence.

## Acceptance (`tests/march.rs`, synthetic terrain via `Terrain::from_fn`; no raw data required)
- **Tempo** (High-Level Design §4.1b): flat terrain, one straight 90 km `FollowRoute` leg with condition `worn`, `foot` profile, posture 620, windows 05:00–11:00 and 15:00–19:00, cycles 50/10, starting D1 05:00. Arrival falls between D4 05:00 and D6 05:00. Assert, and print the arrival time.
- **Monotonic progress:** distance from start never decreases across `SiteReached`/`ColumnDayEnded` events.
- **Accounting independence (property):** for random extra no-op wake-up times inserted into the queue (use a test-only `SimEvent`-free hook `Sim::insert_accounting_checkpoint(t)`, gated behind `#[cfg(any(test, feature = "test-hooks"))]`), final stocks and arrival time are identical to the run without them.
- **Conservation:** initial water − final water = Σ water consumed across the run (recompute independently from the schedule in the test).
- **Thresholds:** water thresholds fire in order 500‰, 250‰, 100‰, each at most once, at times where the remaining amount has just crossed.
- **Events ordered:** journal times are non-decreasing; no column events after `ScenarioEnded`.
- **Snapshot of events:** an `insta` snapshot of the RON-formatted journal for a small 6 km scenario (one day). Review it as a human would; it is the first "story" the game tells.
- Runtime: the 90 km scenario completes in < 1 s in release mode (report, not CI).
- `cargo xtask ci` passes.
