# P1-05 — Terrain import tool

**Agent:** task-implementer · **Size:** M · **Depends on:** P1-06, P0-06 · **Branch slug:** terrain-import · **Runs on:** local

## Goal
Turn the chosen real-world elevation tiles into the game's terrain format: transformed, resampled to 30 m, void-filled, and cut to the Phase 1 strip. After this task, the Red Ledger's ground exists in the engine.

## Specification

### Commands
```
ach terrain import --window content/terrain/red_ledger/window.ron --region strip_p1 \
                   --raw data/raw/terrain --out data/generated/terrain/red_ledger_strip
ach terrain info <dir>
ach terrain preview <dir> --out <png> [--scale-m-per-px 60]
```

### Import (floating point is allowed here: `ach_tools` is not a simulation crate)
1. Parse `window.ron`. `--region` selects `strip_p1` or `corridor_p3`. The output chunk range covers the region bbox (in the local frame) rounded outward to whole chunks.
2. For each output sample (x, y) in the local frame: invert the transform (mirror, then rotation about the window center) to window-local (u, v) meters. Then `lat = lat0 + v / 110_574`, `lon = lon0 + u / (111_320 · cos(lat0))`. Sample the source bilinearly and round to the nearest cm.
3. Source reader: implement **only** the format the ADR selects. SRTM `.hgt` is big-endian i16 on a 3601² or 1201² grid, with void = −32768. GeoTIFF is float32 single band, with the nodata value from the file tags. Mosaic multiple tiles by lat/lon.
4. Voids: fill with the mean of valid samples within a radius of 3 samples, repeating up to 5 passes. Remaining voids ⇒ error listing their coordinates.
5. Detail params: the `DetailParams::default()`. Source info: dataset name, each tile's filename with its `fnv1a64` hex, the transform as text, and the `ach` version.
6. Write through `Terrain::from_fn` + `Terrain::save` so the format stays owned by `ach_world`.

### Info
Print chunk extents, size in km, min/max/mean base elevation (m), void-fill count, and source tiles.

### Preview
Hillshade (azimuth 315°, altitude 45°) with day-palette elevation tints (Field Atlas §3.1), sites and routes from `content/world/red_ledger_*.ron` drawn on top, one pixel per `--scale-m-per-px`.

## Acceptance
- With the raw tiles present, import succeeds; running it twice produces byte-identical output directories (compare file hashes in the report).
- `ach terrain info` shows the strip at 96 × 24 km (±1 chunk rounding) and an elevation range consistent with `RED_LEDGER_REGION.md` (±5 m).
- `ach terrain preview` output, placed next to `docs/canon/red_ledger_region.png`, shows the same landforms and the same site positions. Commit the preview to `docs/artifacts/P1-05/preview.png` and embed it in the PR description.
- Unit tests: the transform inverse for all 8 rotation/mirror combinations round-trips points; the SRTM or GeoTIFF reader passes on a tiny synthetic file written in the test.
- `cargo xtask ci` passes.
