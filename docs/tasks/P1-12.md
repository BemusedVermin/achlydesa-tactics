# P1-12 — Determinism harness, save, and load

**Agent:** task-implementer · **Size:** M · **Depends on:** P1-11 · **Branch slug:** sim-persist · **Runs on:** either

## Goal
Prove the core promise: the same campaign replays identically, and a saved game continues exactly as if it had never stopped. Everything later — replays, the Roll, testimony filling in what happened, the twenty-year handover — depends on this holding forever. Tests written here become permanent guards.

## Specification
```rust
impl Sim {
    pub fn save_snapshot<W: Write>(&self, w: &mut W) -> Result<(), SimError>;
    /// Rebuilds terrain and content from the scenario, then verifies:
    /// header magic ACHS, SCHEMA_VERSION, seed and scenario id match;
    /// content fingerprint matches, unless allow_content_change (then log a warning in the returned struct).
    pub fn load_snapshot<R: Read>(r: &mut R, scenario: &Scenario, repo_root: &Path, allow_content_change: bool)
        -> Result<LoadedSim, SimError>;
    /// Writer positioned to continue this sim's journal: JournalWriter::resume with the state's next_seq, last time, fingerprint.
    pub fn resume_journal<W: Write>(&self, w: W) -> JournalWriter<W>;
}
pub struct LoadedSim { pub sim: Sim, pub content_changed: bool }
```
- `SimState` gains `content_fingerprint: u64`: `fnv1a64` chained over the bytes of every content file named in the scenario plus the terrain `manifest.ron`, in a fixed order (scenario field order).
- The journal state stored in `SimState` must be kept in sync by `step` (it may already be; verify).

## Acceptance (`tests/determinism.rs`, synthetic fixture: two-day march, ~50 km)
1. **Replay:** two fresh runs to the end produce identical journal bytes and fingerprints.
2. **Save/load split (property, 12 cases):** for split times drawn across the run:
   - run to the split, save a snapshot and the journal bytes so far;
   - load into a new `Sim`, resume the journal, run to the end;
   - the concatenation of pre-split bytes and post-split frames equals the uninterrupted journal bytes, and the final fingerprints are equal.
3. **Golden:** an `insta` snapshot of `RunSummary` (fingerprint as hex, event count, arrival times). A comment explains that any change to this snapshot must be justified in the task report.
4. **Content guard:** modifying one byte of the consumption file in a temp copy ⇒ `load_snapshot` returns `ContentChanged` unless `allow_content_change`.
5. **Real data (ignored by default):** `#[ignore]` test that runs the real three-day scenario twice when `data/generated/terrain/red_ledger_strip` exists. Document how to run it.
